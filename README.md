# SF Icon Skill

Claude Code skill that turns any SF Symbols glyph (6000+ icons) into a **Figma-spec inline SVG** ready to drop into any webpage. `currentColor`-based, no font dependency, light/dark mode adaptive out of the box.

---

## What it does

Given a symbol name (`magnifyingglass`, `xmark`, `chevron.left`…) or a SF Symbols PUA character (`􀊫`, `􀆄`, `􀆉`…), this skill outputs clean SVG markup:

```html
<!-- 13pt standard (Figma Button 1) -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 28 28" width="28" height="28">
  <path transform="translate(…) scale(0.008107,-0.008107)" fill="currentColor" d="…"/>
</svg>
```

Paste it into your HTML. Color follows the parent element's `color` CSS property.

---

## Why not [other approaches]

| Approach | Problem |
|---|---|
| Emoji | Renders differently per-OS, inconsistent weight, can't recolor |
| Hand-drawn SVG | Expensive, off-spec from Apple's design language |
| Icon fonts (FontAwesome / Material) | Extra network request, different visual language |
| `<img src="icon.svg">` | Can't adapt to theme, needs separate light/dark files |
| SF Symbols.app copy-paste (PUA chars) | Only renders on Apple devices with the font installed |

This skill: takes Apple's SF Symbols font, renders the glyph path into SVG at Figma-matching scale, outputs `currentColor` paint. Works anywhere, themes correctly, no runtime font fallback surprises.

---

## Requirements

- **macOS** (uses `SF Symbols.app` font file)
- **[SF Symbols.app](https://developer.apple.com/sf-symbols/)** — download from Apple
- **`sfsym` CLI** (optional, for name → codepoint lookup): `brew install yapstudios/tap/sfsym`
- **Python 3** with `fontTools` + `pyobjc-framework-Cocoa`: `pip3 install fonttools pyobjc-framework-Cocoa`

The skill runs a `Step 0` self-check on first invocation and tells you what's missing.

## Usage

Simplest form to Claude:

```
"加 magnifyingglass 13pt"
"用 chevron.left 10pt"
"关闭按钮,用 SF"
```

### Default parameters

| Preset | Size | Weight | Line-height | Box |
|---|---|---|---|---|
| **13pt** (default, Figma Button 1) | 13 | 510 | 22 | 28×28 |
| **10pt** (small) | 10 | 590 | 22 | 20×20 |

Don't change these unless the user explicitly asks. Scale values are calibrated from Figma outline conversion:
- 13pt/wght 510: `scale = 16.75/2066 = 0.008107`
- 10pt/wght 590: `scale = 13/2066 = 0.006291`

### Color

SVG paint is `currentColor`. Set `color: …` on the parent element. For HyperOS design systems:

```css
.my-icon { color: var(--hyperos_color_on_surface); }
.dark-mode .my-icon { color: var(--hyperos_color_on_surface); /* auto adapts */ }
```

## Key features

- **`sf_to_svg(codepoint_or_name, pt=13, …)`** — single icon
- **`sf_batch([…], pt=13, …)`** — batch generate (one font instantiation → 5–10× faster for 10+ icons)
- **Codepoint lookup via pixel comparison** — handles SF Symbols where the font's name table is incomplete (renders the official app's symbol to a bitmap, compares against each candidate glyph)
- **Variable font instancing at `wght=510`** — so the output path weight matches Figma exactly; raw PUA extract would be `wght=400` (too thin)

---

## Token-saving tips (for Claude)

- **Never paste SVG back to the chat.** Write it directly into the target file with `Edit`/`Write`. SVG path `d` strings are 2000+ chars each.
- **Size change ≠ rerun script.** `<svg width="28" → width="20">` scales the whole SVG, no regen needed.
- **Batch > loop.** Use `sf_batch()` for 3+ icons. Don't loop `sf_to_svg()` — each call does a 3–5s font instantiation.

## Troubleshooting

| Symptom | Cause / Fix |
|---|---|
| "Symbol not found: xxx" | Check SF Symbols.app has the symbol (new names in newer releases only) |
| Output weight too thin | Forgot `instantiateVariableFont(wght=510)`; raw glyph is wght=400 |
| Icons render at wrong size in Figma | Use the scale map (13pt/510 and 10pt/590 are calibrated) |
| Path looks jagged in small viewport | SVG is vector — it's not the path, it's your viewport rounding |
